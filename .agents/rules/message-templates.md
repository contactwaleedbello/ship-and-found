# message-templates

Source: PRD Appendix A, Section 11, Section 9.3, Section 2.3.7, Section 3.3 FR-05, FR-07

## Single job

This file holds the exact, verbatim text of every SMS and manual WhatsApp message sent in Version 1, along with the placeholder data-source mapping. `notification-matrix.md` defines *when* and *to whom* each message is sent; this file defines the *exact string* that is sent.

## How to use this file

- Store all templates as typed functions/constants in `lib/templates.ts` (`code-conventions.md`). Do not store templates in the database or in environment variables, because any change to customer-facing financial communication must be code-reviewed against PRD Appendix A.
- Do not reword a template, reorder placeholders, add/remove punctuation, add emoji, or add WhatsApp markdown (`*`, `_`, `~`), because templates are legal and operational records logged in `WhatsAppReminderLog.message_content`.
- Plain text only. English only.

## Placeholder source table

Every placeholder in every template resolves to one authoritative source so no caller invents formatting:

| Placeholder | Data source | Formatting rule | Reason |
|---|---|---|---|
| `[Customer Name]` | `CustomerProfile.full_name` (`data-and-schema.md`) | Plain string, trimmed | Identifies the customer on the contract |
| `[Customer Name if logged in]` | `CustomerProfile.full_name` if authenticated Customer; if unauthenticated Visitor, omit `" My name is [Customer Name if logged in]."` | Conditional suffix on `A.3` only | Visitors have no profile (`PRD 2.1`) |
| `[Device Brand Model]` | `${Device.brand} ${Device.model}` (`data-and-schema.md`) | Single space between brand and model | Matches device card title |
| `[Amount]` | `Agreement.remaining_amount` (`data-and-schema.md`) | Formatted as Naira integer with symbol and commas: `₦80,000` | Prevents ambiguity in currency and amount |
| `[Date]` | `Agreement.due_date` (`data-and-schema.md`) | Converted from UTC to WAT (`UTC+1`) and formatted as `YYYY-MM-DD` | Ensures due date matches Nigerian local calendar (`cron.md`) |
| `[OTP]` | 6-digit numeric code generated by auth service (`security-baseline.md`) | 6 digits (`000000`–`999999`), never logged in cleartext | Required for SMS OTP verification |
| `[Store Contact]` | Shop ATF 03 phone/contact string (unresolved; see below) | Verbatim Appendix A templates already write `"Visit Shop ATF 03 or call us"` inline; if a phone number is appended on Day 0, inject via constant `STORE_CONTACT` | Keeps contact details centralized |

## WhatsApp templates (10 total — PRD Appendix A verbatim)

### A.1 Balance reminder templates (5 triggers from Reminder Checklist)

- **A.1 T-7 (7 days before due date):**
  ```text
  Hello [Customer Name], this is DG Tech Store. Your balance for [Device Brand Model] is [Amount]. Due date is [Date]. Visit Shop ATF 03 or call us to complete payment.
  ```
- **A.1 T-3 (3 days before due date):**
  ```text
  Hello [Customer Name], this is DG Tech Store. Your balance of [Amount] for [Device Brand Model] is due in 3 days on [Date]. Visit Shop ATF 03 or call us.
  ```
- **A.1 T-1 (1 day before due date):**
  ```text
  Hello [Customer Name], this is DG Tech Store. Your balance of [Amount] for [Device Brand Model] is due tomorrow [Date]. Visit Shop ATF 03 or call us.
  ```
- **A.1 T-0 (On due date):**
  ```text
  Hello [Customer Name], this is DG Tech Store. Your balance of [Amount] for [Device Brand Model] is due today. Visit Shop ATF 03 or call us.
  ```
- **A.1 T+1 (1 day after due date):**
  ```text
  Hello [Customer Name], this is DG Tech Store. Your balance of [Amount] for [Device Brand Model] is now overdue. Your contract status will change to Defaulted. Please visit Shop ATF 03 or call us immediately.
  ```

## Composed OTP SMS template (1 template — PRD 9.3 & 11)

PRD Appendix A does not define an SMS body string for OTPs, while PRD Sections 9.3 and 11 require a 6-digit OTP with a 10-minute expiry for registration, forgot-password reset, agreement acceptance, and Worker in-person resend. Use this single composed plain-text SMS body across all 4 OTP triggers so SMS length stays within one 160-character GSM-7 segment:

```text
DG Tech Store verification code: [OTP]. Valid for 10 minutes. Do not share this code with anyone.
```

## Constraints

- Every manual WhatsApp send (`A.1 T-7` through `A.1 T+1`, `A.2`, `A.5`, `A.6`) must log the rendered `message_content`, `trigger_type`, `sent_by`, and `sent_at` in `WhatsAppReminderLog` (`notification-matrix.md`, `FR-07`).
- Never log the rendered OTP SMS body (`[OTP]`) in `AuditLog`, application logs, or Sentry (`security-baseline.md`); log only the OTP trigger event (`OTP_SENT`) without the code.
- URL-encode the rendered message with `encodeURIComponent()` when constructing `https://wa.me/<phone>?text=<encodedMessage>` so spaces and `₦` symbols do not break deep links on Android or iOS.
