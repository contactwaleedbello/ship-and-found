Domain: DG Tech Store (Shop ATF 03)

Endpoint: POST http://127.0.0.1:3000/api/auth/register

curl -i -X POST http://127.0.0.1:3000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"fullName":"a","phoneNumber":"+2348039988771","email":"attacker@domain.com","password":"password123","termsAccepted":true}'

Explanation: Task 3 client-side validation had 8 rules blocking single-character names, but an attacker bypassed the browser completely using curl. The server had no boundary schema enforcement and inserted the junk account into the database.

Explanation: In Task 4, Zod schema validation sits at the server boundary. The single-character name ("a") is evaluated on the server against the domain rule requiring at least 3 characters and at least two words separated by a space. The server rejects the attack with HTTP 422 before any database, password hasher, or downstream service is touched.
